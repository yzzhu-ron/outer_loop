Harness optimization, four ways

How Heuristic Learning, GEPA, Karpathy's autoresearch, and Meta-Harness converge on the same propose–evaluate–keep loop — and what each contributes to optimizing CUA harnesses for web-browsing tasks.

One loop, four instantiations

The shared philosophy

All four works bet that the cheapest remaining gains live in the artifacts around a frozen model, and that an LLM proposer reading rich feedback is the right editor. Their common failure mode is overfitting the evaluator — which makes stable, verifiable, regenerable evaluation loops the scarce input. The broader field map lives in lit-review.html; CUA environment & benchmark work is tracked in applications/shopgym/.

Heuristic Learning: learning as software maintenance

A coding agent maintains a Heuristic System — programmatic policy, state detectors, tests, replays, experiment logs, memory — and "learning" is the agent editing that system in response to feedback. No backprop, no weights. Heuristics were never useless; they were too expensive for humans to maintain. Coding agents change the maintenance curve.

Atari57 detail: at 1M env steps median HNS 0.32 (native-obs) — far above PPO at the same step count. Montezuma is the stated boundary case: 400 pts but as an open-loop 86-macro-action route — reactive if/else needs richer program forms (macro-actions, recoverable search state, long-term memory).

Concepts worth stealing

  • HS anatomy — a single rule file is not a system: policy + detectors + feedback channels + records + replays/tests + memory + update mechanism.
  • Forgetting → engineering — old capabilities pinned as regression tests, fixed-seed replays, golden traces, written-down failed directions.
  • Absorb + compress — a system that only grows becomes a big ball of mud; periodic compression is mandatory.
  • Coupling complexity — what bounds how much system an agent can maintain; clear feedback raises the ceiling.
  • Task shape — "write a policy.py" failed; "maintain a complete loop" worked.

Impact & reception

  • Wide pickup: 36kr coverage ("new paradigm hypothesis"), X circulation; credibility from Weng's OpenAI post-training infra background.
  • Community spin-offs testing boundaries, e.g. xisen-w/hl-imagenet (the blog itself says pure-Python HL can't solve ImageNet).
  • Positioned as candidate next paradigm after RLVR: "anything that can be continuously iterated on becomes solvable."
  • Honest accounting: coding-agent tokens not counted in sample-efficiency claims — acknowledged in the post.

→ Takeaway for CUA harnesses

The HS framing maps 1:1 onto a CUA harness: state detectors = DOM/AXTree/screenshot parsers; policy = action-selection scaffolding; replays = trajectory logs; regression tests = benchmark task suites with binary verifiers. The Atari57 batch protocol (same prompt template × N seeds, required output files) is a ready-made template for batch harness-search experiments.

GEPA: reflective prompt evolution

Genetic-Pareto optimization of any textual parameter. Mutation is an LLM that reads full execution traces and proposes targeted fixes; selection keeps a Pareto frontier over training instances, preserving complementary lessons instead of one average-best candidate.

Adoption

Criticisms / limits

  • overfitting Test perf can peak after a few steps then degrade (seen in deception-detection, Verilog studies) — needs strict val/test splits.
  • weak signal Gains shrink when traces carry little textual feedback.
  • friction DSPy-format requirement for pipelines (mitigated by optimize_anything).

→ Takeaway for CUA harnesses

The most drop-in method: a harness's system prompt, observation-formatting instructions, and action-space description are textual parameters GEPA evolves directly; verifier findings and judge rationales are exactly the "actionable side information" its reflection consumes. Run Pareto selection over task categories, and hold out a strict test split — its documented failure mode is optimization-set overfitting.

autoresearch: the minimal ratchet

Point a coding agent at a single-GPU nanochat trainer and let it experiment overnight: edit → train 5 minutes → measure val_bpb → keep or revert → log → repeat. ~12 experiments/hour, ~100 while you sleep. The whole design fits in three files.

The program.md bakes in a simplicity criterion — "an improvement of ~0 but much simpler code? Keep." That is built-in compression pressure, the same instinct as HL's "compress history."

Reception

  • Fortune dubbed it "The Karpathy Loop"; explainers everywhere (Verdent, MLJAR, The Neuron…).
  • Forks: macOS MLX (val_bpb 2.667 → 1.294 overnight on M4 Max), Windows/RTX, TinyStories variants.
  • "AutoAgent"-style derivatives apply the ratchet to agent harnesses: edit harness, hill-climb benchmark score — the harness-search use case.

Criticisms

  • déjà vu "Rediscovered AutoML" — novelty is the LLM proposer + dirt-simple ratchet, not the concept.
  • Goodhart Agents exploit the metric (Gomoku fork: agent replaced the NN with handwritten alpha-beta search, 99.3% win rate — amusingly, a point for HL).
  • eval noise Unverified viral claims (a "53% speedup" PR stayed unmerged, flagged as overfit). Noisy 5-min runs invite false positives; needs repeat-seed verification.

→ Takeaway for CUA harnesses

The cleanest protocol: one mutable surface (harness code), one frozen evaluator (freeze the verifiers like prepare.py), one metric, fixed budget per iteration, append-only log, keep/revert. The Goodhart lesson is critical: LLM judges are gameable — keep rule-based verifiers as ground truth and aggregate over repeats.

Meta-Harness: the harness optimizes itself

An agentic outer loop searches over harness code — what to store, retrieve, and show a fixed base model. The proposer is a coding agent with unrestricted filesystem access to every prior candidate: source, scores, and raw uncompressed execution traces. It causally debugs past failures and writes new harnesses.

Key diagnosis: prompt optimizers (GEPA included) mutate text and summarize feedback; harness engineering needs the proposer to read whole execution histories and edit arbitrary code. The IMO result shows discovered harnesses transfer across models — search cheap, deploy on stronger models.

Repo practicalities

  • ONBOARDING.md — structured interview → domain_spec.md for a new domain; warns about eval leakage.
  • Reference examples: text-classification memory search, TerminalBench-2 scaffold evolution (Claude Code as proposer via claude_wrapper.py).
  • Fresh release: "not tested beyond verifying that it runs."

Reception

  • Strongly positive: arXivIQ, HuggingFace community report, Softmax Data ("A New Harness in Town").
  • Framed as "Stanford proved it's the harness, not the model" (NerdHeadz).
  • TB-2 leaderboard placement is the headline evidence machine-discovered harnesses beat hand-engineering.

Fit check: Meta-Harness's own criteria vs CUA web-agent benchmarks

long-horizon ✓ repeated episodes ✓ fixed base model ✓ measurable metric ✓ recurring error patterns ✓ stable eval loop ✓

→ Takeaway for CUA harnesses

The closest blueprint: swap "TB-2 scaffold" for "CUA web harness" and TB-2 tasks for web-benchmark tasks. Its hardest prerequisite is a stable, resettable, non-contaminated eval loop — exactly what live-web benchmarks lack. First step in any new domain: run ONBOARDING.md to produce a domain_spec.md.
