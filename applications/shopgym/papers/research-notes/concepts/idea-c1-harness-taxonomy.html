A Taxonomy of Harness Components
and Their Searchability

Map every dimension a CUA harness can vary, measure γ and q₀ for each, characterize the landscape topology, and produce a practitioner-facing "searchability score" per component.

🔥 Hot Systems Empirical

Motivation & Gap

The outer-loop paper (§C) proves that frozen-weight improvement is possible when γ>0 and q₀>0. But it treats the artifact space 𝒜 as abstract. In the CUA / web-agent setting, the artifact is the harness — the scaffolding that wraps a frozen LLM backbone. No existing work has:

  1. Enumerated the full harness design space for web agents
  2. Measured γ per component (how much do execution traces help a proposer improve that component?)
  3. Characterized which components have deceptive landscapes (local optima that fail downstream)
  4. Produced a ranked searchability score a practitioner can use to prioritize outer-loop budget

Meta-Harness (Lee et al. 2026) runs the outer loop but uses a fixed proposer without measuring γ. ShopGym benchmarks harnesses but does not search them. This paper bridges both.

The Harness Design Space — Five Dimensions

A harness is fully described by five orthogonal knobs. Each knob is a discrete or structured choice; the outer loop searches the product space.

Searchability Score — Definition and Predictions

Define the searchability score S(d) for dimension d as a composite of three measurable quantities:

Formal definition

S(d) = γ(d) × q₀(d) / ℓ(d)

where:
  γ(d) — trace-conditioning improvement for proposals touching dimension d
  q₀(d) — baseline proposer success rate on dimension d (prior mass)
  ℓ(d) — median description length (tokens) of a proposal to dimension d

Higher S(d) → dimension d is cheapest to improve via the outer loop.
Low S(d) but high γ(d) → worth expensive search. Low γ(d) → not searchable; engineer manually.

Key Question

Do Observation and Retry dominate the searchability ranking empirically, as predicted? Is the joint search over all 5 dimensions strictly worse than sequential search ordered by S(d)?

Landscape Topology — Deceptive vs. Smooth

The outer-loop theory (§5) shows deceptive landscapes (local ≠ global optimum) require archives, not greedy search. For each harness dimension, we need to know which regime it falls into.

Deceptive landscape — Observation modality

Greedy selector gets stuck at ax_tree; archive escapes to hybrid. Requires archive search.

Smooth landscape — Memory policy

Greedy search works fine. Larger context helps monotonically up to a point; no hidden valleys. Archive adds no value here.

Empirical protocol: for each dimension, run greedy-ratchet vs. archive-ratchet. If archive wins significantly, the landscape is deceptive; record the valley width k (Defn 5.2 of main paper).

Pre-Registered Hypotheses

  • Observation modality has the highest γ across all 5 dimensions, because execution traces directly encode perception failures (e.g., "element not found" after a click).
  • Retry logic has a deceptive landscape: reflective_retry outperforms rollback locally (recovers from single-step errors) but rollback_to_checkpoint outperforms globally (avoids plan commitment errors on multi-step checkout flows).
  • Memory policy has a smooth landscape: performance increases monotonically with retrieval quality up to the context window limit. No deception.
  • Archive search outperforms greedy on deceptive dimensions (H2 above) but matches greedy on smooth ones (H3), consistent with Thm 5.4 of the outer-loop theory.
  • Searchability scores are task-class-specific: on single-page tasks (product search), action space dominates; on multi-step tasks (cart → checkout → confirm), retry logic dominates.
  • Joint search over all 5 dimensions is strictly worse than sequential search ordered by S(d) due to interference (optimizing observation while holding retry fixed finds a local joint optimum).

Experimental Design

Phase 1 — Individual dimension sweep (8 GPU-days)

Task set: 200 ShopGym episodes (stratified: 50 product search, 50 add-to-cart, 50 checkout, 50 cross-page navigation)

Backbone: Claude 3.5 Sonnet, frozen throughout

Procedure: For each dimension d ∈ {mem, obs, act, retry, ctx}:

  1. Hold all other dimensions fixed at their default value
  2. Run 50 episodes at each option variant, collect traces
  3. Measure task completion rate per variant → this is F(a_d)
  4. Condition proposer on traces, re-propose within same dimension → measure γ(d)
  5. Run greedy-ratchet and archive-ratchet for 10 outer-loop steps → compare final F

Output: γ(d), q₀(d), landscape topology, deception flag per dimension

Phase 2 — Sequential joint search (4 GPU-days)

Sort dimensions by S(d) from Phase 1. Run sequential outer-loop search: fix dims 2–5, optimize dim 1 until convergence; then fix dims 1,3–5, optimize dim 2; etc. Compare against:

  1. Fully joint search (random order, all dims simultaneously)
  2. Random ordering (permute dims)
  3. Human-engineered best harness (ShopGym baseline)
Key Output

A searchability score leaderboard — a ranked table any practitioner can use to decide which harness component to budget outer-loop compute on first. The first principled answer to "where should I run my outer loop?"

Connections to Other Work

Meta-Harness (Lee et al. 2026): introduces harness search; does not measure γ or topology. This paper is the theoretical grounding for Meta-Harness design choices.

Outer-Loop theory (main paper, §C + Appendix I): provides the γ estimator and gated-ratchet budget formula used in both phases.

ShopGym (arxiv 2605.16116): the task environment for Phase 1+2; this work makes ShopGym the first benchmark with a formal harness searchability characterization.

GEPA (Guo et al. 2025): shows 35× speedup from trace feedback — this is the empirical γ > 1 claim this paper will measure per-dimension and explain mechanistically.
