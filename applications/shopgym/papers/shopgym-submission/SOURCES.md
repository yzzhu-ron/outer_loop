## Launching the 3 synthetic shops locally

The repo ships as a monorepo of four packages: `shop_arena` (shop factory), `shop_guru` (task generation), `shop_backend` (GraphQL API), and `harness` (plan-then-loop agent engine). The three synthetic shops used in the paper correspond to generated SandboxShops served via `pnpm shop:host`.

### Setup (one-time)

```bash
# Python (shop_arena, shop_guru, harness)
uv sync

# TypeScript (shop_backend + playwright skill)
pnpm install

# Install Playwright Chromium
uv run playwright install chromium

# Verify everything is wired correctly
uv run shop-doctor
```

Copy `.env.example` to `.env` and fill in `OPENAI_API_KEY` (for image generation / ShopGuru eval) and any `ANTHROPIC_API_KEY` / `PI_PROXY_API_KEY` as needed.

### Serving a synthetic shop (no real storefront required)

If the repo includes pre-built SandboxShops (under `outputs/shops/`), serve them directly:

```bash
# List available shops
pnpm shop:host list -a

# Start a shop on an auto-picked port
pnpm shop:host start shop_a              # → Hydrogen on localhost:41xx, GraphQL on localhost:51xx

# Or specify ports explicitly
pnpm shop:host start shop_a 4000         # Hydrogen :4000, GraphQL :5000
pnpm shop:host start shop_b 4100
pnpm shop:host start shop_c 4200

# Stop
pnpm shop:host stop all
```

Hydrogen URL is printed on start; pass it as `shopgym_base_url` to the harness or evaluation script.

### Generating a new SandboxShop from scratch (no live storefront)

```bash
# 1. Generate shop from a manual (skip the explore step if you have a manual)
uv run shop-gen path/to/manual --name my_shop --no-images   # fast, no API key needed

# 2. Serve it
pnpm shop:host start my_shop 4000

# 3. Build ShopGuru benchmark tasks
uv run shop-guru build --shop my_shop

# 4. Run evaluation (requires OPENAI_API_KEY + running shop)
uv run shop-guru eval --shop my_shop
```

### The 3 synthetic shops in the paper

The paper (§4, Table 3) uses three SandboxShops generated by ShopArena from real storefront seeds and validated by structural + behavioral metrics:

| Shop ID   | Domain          | Notes                                             |
|-----------|-----------------|---------------------------------------------------|
| shop_a    | FashionHub      | Apparel — visual-heavy UI, moderate catalog depth |
| shop_b    | TechNest        | Electronics — structured specs, complex checkout  |
| shop_c    | DailyMart       | Grocery/general — large catalog, long journeys    |

Each shop exposes tasks across 7 ShopGuru skill categories: search-exact, search-substitute, browse, filter, shipping, returns, and long-horizon journeys. The `packages/harness` component is the runtime-agnostic plan-then-loop engine used to orchestrate LLM agents against each shop, and is the component our GROL framework replaces/extends with harness search.

### Replacing the internal harness

The paper's §7 references a "BrowserGym harness" (BrowserGym + AXTree) and an "internal screenshot+AXTree harness" (`packages/harness` in the upstream ShopGym repository). The application prototype in [`../../`](../../) treats that internal harness as `h_0 = screenshot + high_level + last_3 + none + once` and searches a five-axis, 900-configuration space. Its committed results come from the seeded mock environment; live ShopGym validation remains a required paper experiment.
