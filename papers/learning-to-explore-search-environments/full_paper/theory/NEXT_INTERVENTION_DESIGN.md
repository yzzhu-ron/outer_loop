# The next decisive test: an observable response with a source-only intercept

**Design agreement, not an empirical result.** Written without computing or inspecting real interior-lambda outcomes. The authoritative registration is [intervention_transfer/protocol.v1.json](../intervention_transfer/protocol.v1.json). Its code, boundary, cost, and evaluation review passed 28 synthetic tests before freeze/evaluation. The source-only-intercept proposal here does not establish that the relationship transfers.

The smallest useful experiment tests utility transfer from a fixed paid panel before learning another probe selector. It compares a source-fixed policy, a pooled response model, and a response model fitted to within-corpus backend changes. The third model uses source centering only while fitting its slope; it never centers target features over unobserved backends.

## Model and observations

Use all 11 policies within two wrapper searches: the five individual actions, including the two-search decomposition, and six RRF60 pairs of the four one-search actions. Original-query retrieval is policy 0. These policies share a search cap, **not identical serving costs**. Keep search, component-search, generation, and token costs separate.

For each sampled document's frozen indirect question, obtain the five action rankings from the one hidden target backend. Compute the 11 policies' known-document reciprocal ranks from those paid lists. For an eight-document panel, define `x_a = mean(RR(policy a) - RR(original))`. Source task labels define `D_a = mean(nDCG(policy a) - nDCG(original))`. Both quantities for the original policy are identically zero. A known source document is a probe label, not a relevance label for a future user question.

For each held-out family, use only the other two families to fit the following. Sort unique source documents by a frozen SHA256 rule; use the first 24 as three disjoint eight-document fitting panels and the next 16 as two disjoint calibration panels. Keep each panel fixed across the seven lambda values. Source fitting utilities use 128 train questions, and source calibration uses its separate 32 questions. Keep documents with invalid generation, charge attempted generation, and use the frozen empty-result behavior without replacements. Hash salts and behavior on insufficient documents must be explicit before outcomes.

For each policy, center `x` and `D` within source corpus/panel across the uniform lambda grid. Fit `beta = Cov(centered x, centered D) / (1.1 Var(centered x))`, with beta zero when variance is at most 1e-6. The pooled comparator instead centers globally. Weight source corpora, panels, and lambda values equally. Repeated utility values across document panels are paired measurements, not independent relevance samples.

Deploy `predicted_gap_a = mu_D_a + eta * beta_a * (x_target_a - mu_X_a)`, with both means taken only from source fitting data. Choose eta from `{0, .5, 1}` on the held-out source documents/questions, without refitting. Tie toward eta zero; freeze policy tie-breaking toward lower cost and then a deterministic policy order. Eta zero is exactly the source-fixed cap-two baseline. This calibration tests new documents/questions in familiar source corpora; it does not establish new-family calibration.

This supplies a **source-only task-utility intercept**. The observed original-query RR supplies a paid probe reference. It does not identify the unknown target task-utility intercept. The assumed transfer is that the source response-to-utility relationship, including its level, remains useful on the target. That is what the experiment must test.

## Deployment boundary and costs

Evaluate each target family/lambda/seed independently, using the first eight documents from its existing pool. The policy receives only declared metadata and selected, charged responses from that one hidden backend. It never receives either endpoint cache, lambda, another target backend's responses, future task queries during onboarding, or target utility labels. If full returned ranklists are available for constructing local RRF policies, declare that interface; do not describe it as delta-only access.

The fixed panel uses six wrapper searches per document: one each for original, keywords, semantic, and HyDE, plus two for decomposition. Total onboarding retrieval is **48 wrapper / 96 component searches**. Computing the 11 policies from those responses adds no retrieval calls. The proposed prefix-generation ledger charges eight document samples, eight joint-question generation bundles, and eight indirect-question rewrite bundles, with exact cached input/output token charges. Generation provenance must justify that prefix ledger. Cache replay itself is not a zero-cost deployment assumption. Source preparation remains a separate offline expense.

## Comparators and decisive diagnostics

The primary comparison is within-corpus fitting against two source-fixed cap-two baselines: the 128-query train prior used by eta zero, and a stronger baseline using all 160 source train/calibration queries with query-count weights within each corpus/lambda, followed by equal corpus/lambda averaging. The latter gives fixed selection the same source label budget as eta calibration. Neither baseline uses target probes. Include pooled fitting, always-original, every fixed policy, all-action RRF, and the full onboarding/serving resource vectors. Report costs amortized over declared future episode lengths; do not equate an LLM call with a search.

A privileged **known-lambda/source-utility comparator** chooses `argmax_a mean_source D[c, lambda, a]`. It sees target lambda, but no target utility labels. It tests whether transferring source action ordering at the correct backend can help. It is not a target-quality upper bound on the response learner: a misspecified source ordering can lose to another predictor.

After every target action is sealed, the evaluator can measure backend-adaptation headroom as `mean_lambda max_a U_target(lambda,a) - max_a mean_lambda U_target(lambda,a)`. A near-zero value means this operator/menu offers little benefit from changing the global policy with lambda, even with perfect information. Keep this oracle distinct from a per-query action oracle.

Also evaluate whether centered target response changes are predicted better than zero changes. Target across-lambda means may appear in this **evaluator-only metric**, never in a deployed feature or intercept. This separates learning backend-induced changes from correctly anchoring absolute action ordering.

For the matched full-pipeline null, permute utility-lambda slices within each source corpus, jointly across all actions, query IDs, document panels, and both train/calibration partitions. Keep probe responses unchanged and target utility untouched. Use one shared permutation across those paired units, refit the slopes, and recalibrate eta. The registration uses 20 permutation seeds. These controls preserve source family means and the source-fixed baseline while breaking the response/utility association. The unshuffled eta-one variant remains a separate diagnostic when source calibration rejects a correction.

Primary aggregation is equal-family averaging under a uniform seven-point engineering lambda distribution, averaging the three observed target pools. Report distinct observable/backend decision states rather than treating seven nearby weights as seven rich independent environments. For descriptive intervals, resample target query IDs within each family and carry each query's complete lambda-by-seed-by-method vector together. Hold the source fit, grid, and pools fixed. Report pool-seed spread separately. The current eight-document target prefixes were checked to be disjoint; this does not make the lambda variants independent domains or include source-fitting uncertainty in the query bootstrap. Three reused families do not support a population-level confirmation claim.

## Suggested advance criteria

The registered engineering gate requires at least +0.005 macro nDCG, positive family means in at least two families, and no family loss worse than -0.005, separately against **both** source-fixed cap-two baselines. Report the conditional intervals; these thresholds are practical decisions, not statistical significance levels. Inspect the complete quality/cost comparison with fixed and all-action fusion alternatives before claiming practical value. The saved practical gate is separate from the mechanism-attribution diagnostics below.

Attribute a gain specifically to within-corpus intervention fitting only if it also improves over pooled fitting, exceeds shuffled alignment controls, and improves prediction of within-target response changes. A successful pooled model alone would support an observable utility bridge, not this particular intervention mechanism. If the known-lambda/source-utility comparator helps but the observed-response learner does not, investigate observability or the bridge's estimation. If neither helps, more probe-selection machinery is not supported for this model. Positive bridge performance with no known-lambda advantage requires a different interpretation, such as predictive corpus-level information in the responses.

## Claim boundary

Centered effects cannot determine action ordering without a level assumption. For two actions, gaps `D_plus(lambda)=1/4+h(lambda)` and `D_minus(lambda)=-1/4+h(lambda)` have identical centered effects. They can share every probe observation while preferring opposite actions. At a lambda where h is zero, any observation-only randomized policy has worst-case regret at least 1/8 across these two utility models. A source intercept is an explicit transport assumption that resolves the model specification; it does not refute this ambiguity.

Within-corpus centering, response-surface regression, known-document pseudo-labels, and source-calibrated action selection are established ingredients. Controlling lambda identifies responses to this engineered backend change; it does not identify a causal effect of probe RR on task utility. This experiment is a mechanism test for transfer under a specified information contract, not a novel causal estimator or acquisition algorithm. See [the literature audit](LITERATURE.md) for the established decision-focused exploration context. A stronger contribution would be a validated transferable bridge with useful failure diagnostics, followed by untouched families and different backend interventions.
