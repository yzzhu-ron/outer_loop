Discussion proposal v0.1 · 9 September 2026 · ICLR 2027 main track target

Learning to Explore Unfamiliar Search Environments Without Task Labels

Can an agent learn which search experiments to conduct before future tasks arrive, then use the results to find evidence more effectively?

Selected from the research shortlist, following the frontier assessment. This document proposes a method and experiments for discussion. No results, novelty guarantees, or acceptance predictions are implied.

Recommended paper target: learn the value of automatically verifiable search probes for improving later retrieval decisions. At a new corpus, the system gets documents and a documented search interface, but no future task queries, relevance judgments, or answers. A small exploration budget produces a compact profile that changes how a frozen agent searches.

The central uncertainty: success on synthetic document-rediscovery tasks may have little to do with success on real user tasks. We should first establish that useful, transferable information exists in those probes, then learn to acquire it efficiently.

Working scope: public text corpora; fixed retrieval indexes and frozen base LLMs during target adaptation; small learned controllers; modest initial compute. The full study is materially larger than the first pilot. These are defaults for refinement, not finalized experimental commitments.

1. The paper we are trying to earn

Candidate claim: a probe-selection policy trained on source environments can identify which self-generated search experiments will improve a search procedure in an unseen environment, using only automatically observable retrieval outcomes there. The resulting improvement transfers to new tasks and repays its exploration cost.

A useful example is technical documentation search. A general agent may alternate between a verbose description, a precise identifier, and decomposed subqueries. The best choice depends on the corpus and index. A short experiment that contrasts these query forms could teach a reusable preference. Finding a particular document once is not enough: the experiment must improve decisions for documents and questions that were absent from exploration.

The proposed scientific contribution is the connection between probe observations and downstream decision improvement. We should not claim to invent active exploration, meta-learning, synthetic queries, procedural memory, or search RL.

Potential contributionEvidence required
A concrete learning methodA learned probe-value predictor beats fixed designs, random probes, and uncertainty-based exploration with the same router, observations, and cost limits.
A transfer resultImprovements survive held-out corpus families, new evaluation documents/entities, and natural changes in retrieval behavior. A task-label-free target phase is enforced.
An explanatory resultProbe-to-task alignment and changes in which search strategy works explain when adaptation helps, fails, or is not worth paying for.

ICLR main-track bar: a substantial learning result with a clear mechanism, credible comparisons, and generalization. A new memory prompt, a benchmark with several search backends, or a small gain over an unadapted agent would not be sufficient. Novelty remains provisional until the concrete algorithm survives comparison with the closest methods.

2. The setting and information contract

An environment is a corpus snapshot, its indexing/chunking choices, a documented search API, and the distribution of future tasks. Our main setting is a read-only retrieval service: the agent can inspect a bounded sample of corpus content and issue queries, but it cannot retrain the backend or rebuild the index.

All methods receive accurate tool syntax, available fields and filters, and a task-type description such as “technical evidence retrieval.” We do not hide basic documentation to manufacture a discovery problem. No method sees the actual future test questions during onboarding. Sampling documents is an explicit capability with an explicit cost; an environment with only a search box and no sampling access is an extension, not the main claim.

StageAllowed informationWhat changes

“Without task labels” refers to adaptation in the target environment. The method can use labeled source tasks and automatically generated target supervision. It is not a claim of learning without supervision anywhere, nor a claim of recursive improvement in the learning algorithm itself.

This is a definition, not a guarantee. The benchmark can estimate it on fixed held-out environments. The total cost of serving NN future tasks is

Report source training separately and charge all target sampling, probe generation, retrieval, profile processing, and extra task-time context. The primary operational comparison concerns quality at matched total serving cost; shared source training is not silently free. If adaptation only saves average task cost Δc>0\Delta c>0, a simple break-even diagnostic is N*=Conboard/ΔcN^*=C^{\mathrm{onboard}}/\Delta c. That expression is not applicable when quality differs; use quality–cost curves then.

3. Proposed method: learn which probes change useful decisions

The first implementation uses a fixed menu of search transformations and two small learned components: a router that chooses a transformation for a real query, and a selector that chooses the next experiment. This makes active selection testable without simultaneously changing a large language model, memory format, and retrieval backend.

1 · GenerateContrastive probes

Two query forms aimed at the same sampled document.

2 · ObserveSearch outcomes

Target rank, result overlap, failures, and cost.

3 · UpdateEnvironment profile

Aggregate evidence about useful query choices.

4 · ApplyFuture search procedure

Route unseen queries using the frozen profile.

3.1 A bounded search-action library

Start with four to six transformations: the original query; a concise semantic rewrite; identifier-preserving lexical terms; a decomposed subquery; and, when documented by the interface, field/filter use. Include a strong reasoning-based rewrite as a baseline action on reasoning-heavy data. Use the same frozen generator and action library for every router. A method must not gain an advantage merely because it receives a better rewriting prompt.

Features can include query length, identifier/number presence, constraint count, entity density, and current search-state summaries. They must be computable at deployment. The initial router may be linear or a small MLP; model size is not the proposed novelty.

3.2 Contrastive document-rediscovery probes

Sample a document and generate an indirect query for it. Produce two transformations that isolate a plausible search choice—for example, preserving an identifier versus paraphrasing it. Run both against the same snapshot. Score whether and where the sampled document is retrieved, rather than asking an LLM to judge its own answer.

Log reciprocal rank or a capped rank score, top-result overlap, empty-result rate, latency, and token costs. Avoid exact title copying and long quoted spans as the only probe family. Include easier probes as controls, but do not confuse rediscovery success with real-task relevance.

For the clean first experiment, the generator reads only the sampled document; the updater and selector receive rank/overlap/cost statistics, not retrieved document text. This prevents probe-result passages from becoming a hidden answer-memory channel. Give the same observations to the primary selection baselines. Treat richer text observations as a separately labeled extension.

These pairs are controlled comparisons of search actions for that synthetic task. They do not, by themselves, identify the effect of an index component or establish utility for real questions. Automatically generated descriptions can also be invalid; use fixed quality checks and audit a sample.

3.3 A profile with deliberately limited content

Use counts, means, variances, and success differences by query-feature bucket and action pair, plus documented schema features. Keep the profile within a fixed size. The main method stores no document text, document identifiers, answers, or entity-to-answer mappings in cross-task memory. A profile of aggregate statistics makes the source of transfer easier to inspect.

The task router combines query features with the profile to select an action. Within a multi-step task, the executor may update ordinary search state, but the environment profile remains frozen. Free-form procedural memory is a strong comparison method and an optional extension; it should not obscure the first causal comparison.

3.4 Learn probe value from actual source-task improvement

On source environments, construct a task-by-action outcome cache using labeled source queries. Sample exploration histories, apply a candidate probe outcome to the profile, and recompute the router’s performance on separate source training tasks. This yields a target for the probe-value predictor:

ve(p,H)=U^e(U(H∪{(p,op)}))−U^e(U(H))−λc(p).v_e(p,H)=\widehat U_e\!\left(U(H\cup\{(p,o_p)\})\right)-\widehat U_e\!\left(U(H)\right)-\lambda c(p).

Here U^e\widehat U_e uses real source-task labels; opo_p is observed only after executing the probe. Train a predictor gθ(H,φ(p))g_\theta(H,\varphi(p)) using features available before the next target probe is run. During target adaptation it chooses the highest predicted useful probe, updates the profile, and stops when the budget is exhausted or predicted gains are too small. Select the stopping threshold on development environments.

The initial source cache measures single-step evidence retrieval; it does not supply counterfactual multi-step task returns. In the first end-to-end test, use the learned choice for the first retrieval step and keep the executor’s subsequent behavior unchanged. Applying the router at every search round is a secondary experiment until suitable source search-state labels are collected.

The first selector can imitate a one-step oracle teacher through regression or pairwise ranking. This is explicitly a myopic value estimate. Multi-step exploration RL is a possible extension only if the myopic pilot reveals a material planning limitation.

Implementation order and controls against hidden advantages
  1. Fix query transformations, features, profile representation, and the executor. Measure the best global action and a task-label oracle’s action-selection ceiling.
  2. Train a router on source environments with varied probe histories. Freeze it while generating probe-value labels so the label represents the effect of new evidence.
  3. Train a small value predictor against those source labels. Validate on held-out environments, not randomly split rows from the same corpus.
  4. Compare learned, random, fixed-coverage, uncertainty, and information-gain probe selection using the identical updater/router. This isolates selection.
  5. If the first pass works, alternate router and selector training in controlled rounds. Report each component’s training cost; do not introduce large-agent RL before the small-controller hypothesis is tested.

At target time, candidate generation and document inspection are charged. An unselected probe cannot have its search outcome available to the selector. A precomputed target pool is permissible only with its construction cost included and identical access for comparisons. Cached source outcomes accelerate research; they do not make target evidence free.

4. Novelty boundary and required closest comparisons

The tighter formulation makes the project more testable, but it also exposes substantial prior art. We should position it as a candidate solution to a specific adaptation problem, not as the first agent that learns from experience.

5. Falsifiable hypotheses and the failure cases that matter

HypothesisDiagnosticWhat would undermine it
H1 · There is something useful to learn about the environment.Different natural environments favor different actions, and an oracle router improves real-task outcomes over the best universal strategy.The same strategy wins nearly everywhere, or the oracle advantage is negligible.
H2 · Probes contain transferable task-useful information.Profiles predict action utility on unseen documents/queries better than interface descriptions and static source priors.Probe success merely tracks lexical overlap or document popularity and fails to predict real-query performance.
H3 · Deliberate selection is worth learning.The learned selector beats random, fixed-coverage, and uncertainty baselines with an identical router and budget.Random probes or a fixed balanced design recover the same benefit.
H4 · The benefit is procedural and operational.Gains survive disjoint documents/entities, profile transplantation controls, and comparison against spending the same cost during user queries.Answer overlap, additional context, or extra total compute explains the effect; onboarding never pays back at a plausible workload.
A modest theory component, only if it explains the experiments

There is no universal reason a self-generated probe should predict utility on an unknown future task distribution. Two environments/task distributions can produce indistinguishable probe observations but favor different actions. No selector restricted to those observations can always choose correctly.

Conversely, in a simplified finite-action model, if a profile-based estimate approximates each action’s true mean task utility within ϵ\epsilon, choosing the estimated best action incurs at most 2ϵ2\epsilon selection regret. That is a standard observation, not an ICLR contribution by itself.

A useful theoretical extension would characterize when the probe family identifies action ordering, rather than reconstructing every property of the environment, and relate this to measured transfer failure. Only pursue it if the empirical results expose a nontrivial boundary. Do not promise an unrestricted guarantee for future corpora.

6. Evaluation design: enough separation to support the claim

Corpus families are the main unit of transfer

Define a corpus family by shared underlying content/provenance. Wikipedia-derived QA datasets are not independent environments merely because their benchmark names differ. Group related collections before splitting. Use source families for learning, separate development families for all choices, and untouched target families for final reporting.

A working full-study target is four source families, two development families, and three final target families, each with a small set of natural retrieval configurations. This is a planning target, not a claim that those datasets and caches are already ready. If the final target panel remains small, show all family results and make a bounded empirical claim; do not infer a universal success probability over future environments.

BRIGHT needs a strong reasoning-rewrite comparison.
End-to-end agent testAt least two naturally distinct task/corpus families with answer and evidence annotations, using the same frozen executor before/after adaptation.Show that improved retrieval produces useful task outcomes. A retrieval-only result does not establish better autonomous task solving.
Controlled environment changesOn the same content: sparse/dense/hybrid search; defensible chunking or field configurations. Provide accurate documentation to all methods.Separate corpus-content changes from search-behavior changes. Treat configurations of one corpus as correlated.

Do not begin by manufacturing opaque backends with arbitrary hidden rules. Use controlled variants to explain a result that also appears under natural shifts. Keep the evaluation corpus intact when creating probe/test splits; deleting hard negatives or irrelevant documents can change the retrieval problem.

Prevent answer storage and invalid evaluation

  • Partition document or duplicate/entity groups into an exploration-seed pool and a held-out pool before running methods. The evaluator selects queries whose annotated support belongs to the held-out pool, using the same eligibility rule for every method. Leave both pools in the search index. Report how much of the original query set remains; the runtime selector never sees the query labels or inclusion decisions.
  • Audit duplicate content and entity overlap. Include a stricter entity-disjoint slice when feasible, and label the change in task distribution rather than pretending all splits are interchangeable.
  • Run a profile-swap experiment: transfer the profile between two corpus slices with the same search configuration, and between configurations with different behavior. Keep task content fixed where possible.
  • Compare against no-search and oracle-evidence conditions. Verify that correct evidence exists in the chosen corpus snapshot before attributing failures to the agent.
  • Use coherent fact changes as an optional supporting control, not the whole benchmark. Check answerability and retrieval difficulty after the transformation.

Known-document probe scoring cannot establish that other documents are irrelevant. Keep that distinction explicit. Incomplete qrels also affect the evaluation of new query transformations; pool and audit a blinded sample of novel top results if missing judgments materially alter conclusions.

8. Outcomes, uncertainty, and the main figures

Primary retrieval endpoint: equal-family macro nDCG@10 on untouched target queries, comparing methods under a predeclared total serving-cost cap for a reference workload. Start with N=50N=50 future tasks for planning, then show N∈{1,10,50,200}N\in\{1,10,50,200\}. These values must be frozen before final results are inspected.

Use development runs to select eligible budget configurations under that cap. Report actual costs and quality–cost curves for every method, including no adaptation. Do not conceal a cost overrun behind a nominal “same number of probes.” Sweep exploration budgets such as 0, 16, 64, and 256 tool operations, with a separate token ceiling; a paired probe consumes multiple operations. Count sampling and opening documents as well as searches.

Required secondary outcomes: task success with evidence on the end-to-end evaluation; evidence recall; selected-action regret relative to an oracle; invalid/degenerate probe rate; profile size; onboarding and serving costs separately; and sensitivity to task mix. Select one primary endpoint in the frozen protocol rather than declaring whichever metric improves to be the win.

9. The smallest pilot that can change our mind

First output: a short result ledger and three plots—action-selection headroom, probe-to-task alignment, and adaptation benefit versus cost. No large-agent training is needed to obtain them.

  1. Verify the environment. Pin two small public corpus snapshots and two search configurations each. Audit document availability, probe/test separation, and a few answer/evidence examples. Preserve the full corpora.
  2. Measure headroom. Evaluate the same small action library on real queries. Compare a global strategy, a global query-conditioned router, and a task-label oracle. If routing cannot help, active exploration cannot rescue this design.
  3. Test proxy usefulness. Generate a bounded probe set; compare profile predictions with action utility on disjoint real queries. Include exact-overlap versus indirect probes and simple lexical/popularity controls.
  4. Test active choice. Train a minimal source-only selector and compare it with random, fixed-coverage, and uncertainty selection using an identical router. Rotate pilot roles only for debugging and label these results exploratory.
  5. Make the research decision. Inspect negative cases and total cost before expanding the corpus panel or changing the base model.
GateProceed whenStop or revise when
A · HeadroomThe oracle has a practically meaningful advantage in more than one natural environment; a provisional screening target is 0.05 absolute nDCG@10.One global strategy or the ordinary router is already near the ceiling.
B · Transferable signalProbe profiles help on unseen real queries and documents beyond descriptions, source priors, and overlap heuristics.Only synthetic rediscovery improves, or content overlap explains the benefit.
C · Active selectionLearned choice improves over strong passive/active baselines across pilot seeds at a useful effect size.Fixed coverage or standard uncertainty sampling is equally good. Do not preserve a learned-selector story by weakening baselines.
D · Operational valueThe gain survives total-cost accounting and has a plausible workload at which onboarding is worthwhile.Extra query-time compute dominates, or gains require impractical numbers of future tasks.

The numerical headroom screen is a discussion default, not a significance threshold or promised result. Freeze practical effect targets with the protocol before confirmatory testing. A pilot with 100–200 questions per environment is for detecting large opportunities and gross confounds, not for certifying small effects.

Prospective abstract for discussion — no result claims

Search agents often encounter unfamiliar corpora and retrieval services whose useful query strategies differ from those seen during training. We study whether an agent can adapt before receiving its future tasks by conducting a bounded number of automatically verifiable search experiments. Our proposed method learns, on source environments, which contrastive document-rediscovery probes improve downstream retrieval decisions. At deployment it uses only corpus samples and search outcomes to update a compact environment profile, while keeping the search index and base agent fixed. The planned evaluation separates corpus families, prevents answer storage in the profile, and charges the complete cost of exploration and subsequent task solving. It tests whether learned probe selection improves quality and cost over strong static, passive, active-learning, and synthetic-adaptation baselines, and identifies when synthetic probe outcomes fail to transfer to real tasks.
