The Outer Loop

A Unified Theory of Gradient-Free LLM Improvement Loops

28 slides · ~50 min

Navigate: ← → arrow keys, or buttons below  ·  ← Back to project page

Motivation

How do LLMs get better — without retraining?

We're used to thinking about ML as: train → deploy → done. But a whole new paradigm has quietly emerged:

The Outer Loop Pattern
Take a frozen LLM. Let it edit a text artifact — a prompt, a skill, a harness, a training script. Score the result. Keep what's better. Repeat. Never touch the model weights.

Examples you've heard of

  • GEPA — LLM evolves its own prompt by reflecting on traces
  • Meta-Harness — rewrites scaffolding code around frozen model
  • AlphaEvolve / FunSearch — evolves programs against math evaluators
  • Karpathy's autoresearch — edits its own training codebase overnight
  • Heuristic Learning — patches heuristics from replayed failures

The problem

Each system was described with its own vocabulary — reflection, evolution, context engineering, self-improvement. Each paper's analysis is empirical.

This leaves basic questions open. This paper answers them.

The Questions We Answer

Six basic questions, left open until now

❓ Why so sample-efficient?

Why are these loops surprisingly good when classical program search is provably hopeless?

❓ When do traces matter?

When does a scalar reward suffice, and when do you need structured execution traces?

❓ Why does it overfit?

Why do greedy prompt optimizers sometimes overfit their validation sets?

❓ Why do results fail to replicate?

Why do noisy single evaluations produce "celebrated improvements" that later collapse?

❓ Why archives everywhere?

Why do archives and Pareto frontiers keep appearing in independently developed systems?

❓ Can you certify improvement?

Is there a sound test that guarantees a candidate is actually better than the incumbent?

01

The Anchor Papers

Four systems that inspired this theory — what they did, and what they left unexplained

Anchor Paper 1 of 4

Heuristic Learning (HL)

Learning Beyond Gradients
Weng (2026) · Blog post / Technical report
Key claim: patch executable heuristics from replayed failures · No gradient step ever taken

The setup

Take a Python function (a "heuristic") that scores or selects actions. When it fails on a real episode, replay that episode to the LLM and ask it to patch the code. Run tests. Keep the patch if tests pass.

The artifact = the heuristic code
The evaluator = execution tests on replayed episodes
The proposer = frozen LLM with failure trace as context

What it showed

LLMs can reliably improve task-specific heuristics without any weight update, using only execution feedback from failures.

What it left open

  • How many proposals before success?
  • When does noise in evaluation mislead?
  • How much does the trace help vs. scalar reward?
Anchor Paper 2 of 4

GEPA — Gradient-free Evolutionary Prompt Adaptation

GEPA: Evolving Prompts via Execution Traces
Agrawal et al. (2026) · ICLR 2026 Oral
Key result: outperforms GRPO (RL) with up to 35× fewer rollouts

The setup

A population of prompts. Each prompt generates a response; execution is traced. The LLM is shown the trace and asked to mutate the prompt to do better. A selection step keeps the winners.

Evolutionary framework, but no gradient signal. The LLM itself is the mutation operator, conditioned on rich execution traces.

Why 35× fewer rollouts?

The structured trace gives the LLM information that scalar reward does not — the equivalent of "first-error feedback" in our theory (Theorem 4.2).

The open question

How much is the trace actually worth — can we quantify it? Yes: exponential separation (our §4).

Anchor Paper 3 of 4

Karpathy's Autoresearch

autoresearch: an LLM edits its own training codebase overnight
Karpathy (2026) · GitHub / Technical report
The artifact is the training code itself · Evaluator = validation loss

The setup

A frozen LLM is given a training codebase and a validation loss metric. It proposes edits — hyperparameter changes, architecture tweaks, data pipeline fixes. Each edit is evaluated by running training. The best edits accumulate.

This is the outer loop applied to ML research itself. The loop searches artifact space (code) not weight space.

Why it matters for theory

The evaluator here (validation loss from a training run) is extremely noisy. Any single evaluation could mislead.

This motivates our ratchet illusion analysis (§5) — and the gated certification theorem (Theorem 6.1).

Anchor Paper 4 of 4

Meta-Harness

Meta-Harness: Self-Improving Evaluation Scaffolding
Lee et al. (2026) · Stanford IRIS Lab
Key result: beats hand-built context management on multiple benchmarks

The setup

Instead of tuning the agent, tune the scaffolding around it — the code that manages memory, tool calls, retry logic. The LLM evaluates each scaffolding version by running benchmark tasks. Keeps what works.

The artifact = harness code (not agent weights)
Insight: the harness is often the bottleneck, not the model

Why archives appear

Meta-Harness naturally maintains a Pareto archive of scaffolding versions — trading off different capabilities. Our theory explains why archives are exponentially better than greedy search (Theorem 5.4).

For web agents (like ShopGym)

The harness-search idea extends directly to e-commerce CUA benchmarks.

03

Resource 1: Prior Mass

Why frozen LLMs find good artifacts faster than random search — and how to measure the boost

§3 · Theorem 3.2

The LLM as a prior — not just a proposer

The key insight

Think of the LLM as a distribution over artifacts. The fraction of that distribution landing in the "good" region — the prior mass on Gε — is what determines speed.

Theorem 3.2 (Hitting Time)
Expected proposals until finding an ε-good artifact ≈ 1 / q₀(Gε)

Like Levin's universal search — but the LLM is the prior.

The trace-conditioning boost γ

When the LLM sees execution traces (failures, partial results), it proposes better. The boost factor γ ≥ 1 measures how much:

𝔼[proposals] ≈ 1 / (γ · q₀(Gε))

Good news: γ is measurable (Proposition 3.5). You don't have to guess it — you can estimate it from a finite sample of verified proposals with a pre-registered protocol.

Practical meaning: An LLM trained on lots of code will have high q₀(Gε) for coding tasks — so the outer loop is fast. Random search would need 1/q₀ proposals with γ=1; the LLM gets there γ× sooner.

04

Resource 2: Feedback Information

Scalar rewards vs. structured traces — why GEPA's 35× speedup is theoretically inevitable

§4 · Theorem 4.2

Three types of feedback — exponential separation

Imagine an L-bit secret (a target artifact). How many queries to find it?

Worst

Scalar 0/1 Reward

2L/2

Only told pass/fail. Must search all 2L possibilities. Exponential in artifact length.

Better

Distance Feedback

L+1

Told Hamming distance to target. One probe per bit. Linear — already exponentially better.

Best

First-Error Trace

L/2

Told which bit fails first. Can fix greedily. Only half the bits need probing on average.

Theorem 4.2 — Exponential separation
Scalar reward requires Θ(2L) queries. First-error feedback requires only O(L) queries. This is the theoretical explanation for GEPA's 35× fewer rollouts vs. RL with scalar reward.
05

The Ratchet Illusion

The most dangerous result in the paper — fake improvements from pure noise

§5 · Theorem 5.1

3.4σ from absolutely nothing

The experiment

Run a greedy ratchet on null edits — every single edit has true value = 0. The only signal is evaluation noise.

Accept an edit whenever it scores higher than the running maximum.

Result (Theorem 5.1, simulated)
After 2,000 null edits:
3.4σ median reported "improvement"
True improvement: exactly 0

Why this happens

Each accept is a record of an i.i.d. sequence. The expected number of records up to time t is Ht = Σ 1/i ≈ ln t — it grows without bound.

The reported best converges to σ√(2 ln t) — it also grows without bound, purely from statistics of maxima.

Real-world consequence
If your evaluator has noise σ=1 and you run 2000 evaluations, you will see a 3.4σ "improvement" even if every edit is useless. This is why celebrated results fail to replicate.
§5 · Corollary 5.3

The fix: the repeat-gated ratchet

The solution

Before accepting any candidate, evaluate it N times and accept only if the mean score is ≥ Δ/2 above the incumbent.

N = ⌈ (8σ²/Δ²) · ln(B/δ) ⌉

For σ=1, Δ=1, B=2000 candidates, δ=0.05 failure probability:

N = 85

repeats per decision certify the entire run

What the gate buys you

With N=85 repeats, false accept probability per decision ≈ 2 × 10⁻⁶.

Across 800,000 decisions: expected 1.6 false accepts. Observed in simulation: 2.

Corollary 5.3 — Certified ratchet
With gate N, the probability that the final artifact is not a genuine Δ-improvement is ≤ δ. The whole run is certified — not just the last step.

The cost is N× more evaluations per decision. Theorem 6.1 tells you whether that cost is worth it given your specific γ and q₀.

Deceptive Landscapes

Why archives appear everywhere — and why they're not just a trick

§5 · Theorem 5.4

Valleys that trap greedy search — archives escape

The landscape model

A k-wide valley: to reach the global optimum, you must first pass through a region where every step locally looks worse.

▲ Global opt
          / 
         /  ← uphill, but greedy
  Start  \     must go down first
          \____/
        valley (width k)

Greedy vs. Archive

ε-tolerant greedy

Sometimes accepts worse moves (prob ε). Must get lucky k times in a row to cross the valley.

Expected time: Ω(ε−k) — exponential in valley width

Archive search

Keeps all visited states. Explores the valley breadth-first. No lucky streak needed.

Expected time: O(k²) — polynomial in valley width

This is why AlphaEvolve, Meta-Harness, and other top systems independently invented archives and Pareto frontiers.

§7 · Theorem 7.1

Resource 5: Description Length & the U-Shape

The Occam bound

The artifact has a description length ℓ(a). A shorter artifact generalizes better (Occam's razor). But too-short artifacts can't express the solution.

Theorem 7.1
Generalization error ≤ training error + O(ℓ(a) / n)
where n = number of validation points

Longer artifacts overfit. Shorter artifacts underfit. The optimal length is a U-shaped tradeoff.

Two failure modes it predicts

Context collapse (too short)

Artifact is compressed below information content of the task. Performance degrades — observed in over-pruned prompts.

Validation overfitting (too long)

Artifact is longer than n bits — it memorizes the validation set. "Prompt hacking" — prompts that pass validation but fail deployment.

The bound gives a principled answer to "how long should my prompt be?"

The Composed Theorem

Putting all five resources together — a single certified-improvement guarantee

§6 · Theorem 6.1 — Key result

Certified Improvement Theorem

Theorem 6.1 — Composed Certified Improvement
A gated artifact-search loop finds and soundly certifies a Δ-improvement over the incumbent (failure prob ≤ δ, across B candidates) using at most:

C = (8σ²/Δ²) · ln(B/δ) · ln(1/δ) / (γ · q₀(Gε))

evaluator calls in expectation.
False-reject slowdown: explicit factor (1 − δ/B).

What each term means

  • 8σ²/Δ² — noise-gap ratio (ratchet §5)
  • ln(B/δ) — gate size (certify across B candidates)
  • ln(1/δ) — hitting time factor (prior mass §3)
  • γ — trace-conditioning boost (§3)
  • q₀(Gε) — proposer's prior mass on good set (§3)

Why it matters

For the first time, you can compute whether running a gated outer loop is worth it before you start: plug in your σ, Δ, and estimated γ.

All five resources appear — and they multiply: improving any one improves the total budget. The theory tells you where to invest.

§8 — Limits

When the evaluator is also an LLM: Goodhart's Law

The in-model evaluator

What if F̂ is itself an LLM? (LLM-as-judge, reward models, self-evaluation)

Proposition 8.1
If F̂ : 𝒜 → [0,1] is realized by a bounded LLM, then for any target value v, there exists an artifact a with F̂(a) ≥ v.

The reward is range-filling: the model cannot distinguish its optimization target from all other high-scoring artifacts.

Real examples

Jailbreaks

Adversarial prompts that score high on an LLM evaluator but are harmful — the evaluator has been "gamed".

Prompt hacking

Prompts that score perfectly on the validation set of a frozen evaluator but fail on unseen tasks.

Goodhart's Law formally: "When a measure becomes a target, it ceases to be a good measure." Proposition 8.1 is the precise version.

§M — Falsifiable Predictions

Five predictions you can test

The paper makes testable scaling predictions — not just post-hoc explanations:

P1

γ scales with model size — larger LLMs have higher trace-conditioning boost γ, making the outer loop faster.

P2

Trace feedback beats scalar by Ω(2L/L) — measurable on any coding benchmark with controllable artifact length L.

P3

Single-eval ratchet false-positives scale as ln t — observable in any deployed system by tracking accept history.

P4

Archive search wins on deceptive benchmarks — measurable by comparing archive vs. greedy on tasks with known local optima.

P5

Prompt length has a U-shaped test-error curve — measurable on any prompt optimization benchmark with varying artifact length.

Pre-registered measurement protocol for γ in Appendix I: 120 buggy programs, 70 patches/condition, Wilson confidence intervals, falsifier pre-stated.

Summary

What you should take away

The theory in one sentence

Every frozen-LLM self-improvement loop runs the same outer loop. Its behavior is governed by five measurable resources. Theorem 6.1 gives you the evaluator budget — before you run a single experiment.

If you remember one result

The Ratchet Illusion: a greedy ratchet on pure noise reports 3.4σ of "improvement" at t=2000. Always gate your evaluations. Gate size N=⌈8σ²/Δ² · ln(B/δ)⌉.
